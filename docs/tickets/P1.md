## P1-01 — User model + bcrypt hashing

**Depends on:** S-01 · **Size:** M · **Branch:** `feat/p1-01-user-model`

**Files**
- Create: `models/user.model.js`
- Create: `test/user.model.test.js`
- Add dep: `bcrypt`, and dev deps `mongodb-memory-server`

**Interfaces — produces**
- `User` Mongoose model. Fields: `username` (String, required, unique, lowercase, trim),
  `passwordHash` (String, required, `select: false`), `role` (String, enum `['reporter','editor']`, required),
  `displayName` (String, required), `active` (Boolean, default `true`), `timestamps: true`.
- Instance method `user.setPassword(plain)` → sets `passwordHash` to a bcrypt hash (cost 12).
- Instance method `user.verifyPassword(plain)` → `Promise<boolean>`.
- `createUser({ username, password, role, displayName })` → `Promise<User>` (new doc, password hashed, saved). Export from this module.

**Test first** (`mongodb-memory-server`, one connection in a `before` hook):
- missing `username` / `role` / `displayName` → validation error.
- duplicate `username` (case-insensitive) → duplicate-key error.
- `role: 'admin'` → validation error; `'reporter'` and `'editor'` → ok.
- default find does **not** include `passwordHash`; `.select('+passwordHash')` does.
- `setPassword('secret')` then `passwordHash` ≠ `'secret'` and starts with `'$2'`.
- `verifyPassword('secret')` → `true`; `verifyPassword('wrong')` → `false`.
- `createUser({...})` persists a doc whose `verifyPassword` matches the given password.

**Acceptance**
- [ ] All test cases above pass; watched them fail first.
- [ ] `bcrypt` cost is 12, defined as a named constant.
- [ ] No plaintext password is ever assigned to a persisted field.

**Commit:** `feat: add User model with bcrypt password hashing`

## P1-02 — Session store (connect-mongo) + Restart proof

**Depends on:** P1-01 · **Size:** M · **Branch:** `feat/p1-02-session-store`

**Files**
- Create: `config/session.js`
- Create: `test/session.test.js`
- Add deps: `express-session`, `connect-mongo`
- Modify: `app.js` — add `app.use(sessionMiddleware)` at the marked seam (after `express.json()`, before `/api`). Coordinate with P5 (ticket P5-02).

**Interfaces — produces**
- `export function sessionMiddleware()` → configured `express-session` handler.
  Cookie: `httpOnly: true`, `sameSite: 'lax'`, `secure: env.nodeEnv === 'production'`, `maxAge: 7 days`.
  Store: `MongoStore.create({ client: mongoose.connection.getClient(), collectionName: 'sessions', ttl: 7 days })`
  — **reuse the existing Mongoose connection**; do not open a second connection via `mongoUrl` (ADR 0001 + TEAM-PLAN §5).
  `secret: env.sessionSecret`, `resave: false`, `saveUninitialized: false`.

**Test first**
- Build **two** separate `createApp()` instances that share one `mongodb-memory-server` URI.
  Each app mounts `sessionMiddleware()` and two tiny routes: `POST /_login` sets `req.session.user = { id: 'u1', role: 'editor' }`; `GET /_who` returns `req.session.user ?? null`.
- `POST /_login` on app A → capture the `Set-Cookie`.
- `GET /_who` on **app B** with that cookie → returns `{ id: 'u1', role: 'editor' }`.
  (App B never saw the login; the session came from Mongo. This is the Restart guarantee.)
- `GET /_who` on app B with no cookie → `null`.

**Acceptance**
- [ ] Cross-instance test passes; watched it fail first (e.g. with `MemoryStore` it fails).
- [ ] `app.js` seam filled; `npm test` still green including the skeleton suite.
- [ ] No secret literal in `config/session.js` — only `env.sessionSecret`.
- [ ] Store reuses `mongoose.connection.getClient()`; no second Mongo connection opened.

**Commit:** `feat: store sessions in MongoDB so login survives a restart`

## P1-03 — Auth endpoints: login / logout / me

**Depends on:** P1-01, P1-02 · **Size:** M · **Branch:** `feat/p1-03-auth-endpoints`

**Files**
- Create: `controllers/auth.controller.js`, `routes/auth.routes.js`
- Create: `middleware/auth.js` with `loadUser` only (P1-04 adds the guards)
- Create: `test/auth.routes.test.js`
- Modify: `routes/index.js` — `apiRouter.use('/auth', authRoutes)`
- Modify: `docs/API-CONTRACT.md` — fill the Auth section

**Interfaces — produces**
- `POST /api/auth/login` `{ username, password }` → 200 `{ data: { id, username, role, displayName } }`, sets session; 400 if a field is missing; 401 `invalid credentials` for bad username **or** bad password (same message — no user enumeration).
- `POST /api/auth/logout` → 200 `{ data: { ok: true } }`, destroys the session, clears the cookie.
- `GET /api/auth/me` → 200 `{ data: { id, username, role, displayName } }` when authed; 401 otherwise.
- `loadUser(req, res, next)` — if `req.session.user`, load the User by id, set `req.user`, and mirror the session snapshot role onto `req.user.role` (do **not** overwrite it with the live DB role — RBAC uses the snapshot, per D4 + ADR 0001). `active` is the only field checked live: if the user is missing or `active === false`, destroy the session and treat as anonymous. Mount it in `app.js` after the session middleware.
- On login store only `req.session.user = { id, role }`.

**Test first** (`supertest`, seeded user via `createUser`)
- login, missing `password` → 400.
- login, unknown username → 401, body message `invalid credentials`.
- login, known username + wrong password → 401, same message.
- login, correct → 200; body has `id, username, role, displayName`; body has **no** `passwordHash`; response has `Set-Cookie`.
- `GET /me` no cookie → 401; with the login cookie → 200, same shape.
- `POST /logout` with cookie → 200; a subsequent `GET /me` with the same cookie → 401.
- deactivate the user in the DB, then `GET /me` with a still-valid cookie → 401 (loadUser kills it).

**Acceptance**
- [ ] All cases pass; watched them fail first.
- [ ] `logger.info('auth.login.success', { userId })`, `logger.warn('auth.login.fail', { username })`, `logger.info('auth.logout', { userId })` emitted.
- [ ] Auth section of `docs/API-CONTRACT.md` written.

**Commit:** `feat: add login, logout and me endpoints`

**Interfaces — produces**

**Test first** (mount the guards on throwaway routes in the test)
- `requireAuth`: no `req.user` → 401 envelope `{ error: { code: 'unauthorized' } }`; with `req.user` → route body returns.
- `requireRole('editor')`: `req.session.user.role = 'reporter'` → 403 `{ error: { code: 'forbidden' } }`; `'editor'` → passes.
- `requireRole('reporter', 'editor')`: either role passes; no `req.session.user` → 401.

**Acceptance**
- [ ] Cases pass; watched them fail first.
- [ ] Failures go through `next(AppError...)` — no hand-built JSON in `auth.js`.
- [ ] `docs/API-CONTRACT.md` shows the exact import + a usage example; ping P2 and P4 that it is merged.

**Commit:** `feat: add requireAuth and requireRole guards`
